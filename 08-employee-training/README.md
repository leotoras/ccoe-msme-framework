# Component 8 — Employee Training

Open courseware for client-side staff, so that governance capability remains with the organization
after an engagement ends.

**Output:** Delivered sessions with recorded completion
**Audience:** IT staff and, for one module, all staff with cloud access

---

## Why this component exists

A governance framework operated by an outside party is a dependency. A governance framework the
client's own staff can run is a capability. This component is what makes the difference, and it is
the reason the framework does not create a permanent consulting relationship.

---

## Module 1 — Cloud governance fundamentals *(IT staff, 90 min)*

| Topic | Covers |
|---|---|
| What a CCoE is and is not | Standing function versus one-off project |
| The nine components | What each produces and why the order matters |
| Reading the maturity assessment | Scoring honestly; the 2→3 verification boundary |
| Ownership | Who decides, who implements, who reviews |

**Exercise:** Score two domains of the maturity assessment for your own environment.

## Module 2 — Security baseline in practice *(IT staff, 2 hours)*

| Topic | Covers |
|---|---|
| The foundational controls | Audit logging, configuration recording, storage exposure, identity |
| Deploying the baseline | Running the Terraform, reviewing the plan, what it does not cover |
| What Terraform cannot enforce | MFA enforcement, root protection, and why they are manual |
| Verifying | The CLI checks that confirm each control is live |

**Exercise:** Run the verification commands against your own account and record the results.

## Module 3 — Cost accountability *(IT staff and budget owners, 90 min)*

| Topic | Covers |
|---|---|
| Baseline before optimization | Why an unmeasured saving is not a saving |
| Attribution | Tagging versus account separation; measuring coverage |
| The monthly waste review | The seven categories and how to work them |
| Commitments | When to commit, when not to, quarterly review |

**Exercise:** Identify three attribution gaps in your current environment.

## Module 4 — Resilience *(IT staff, 90 min)*

| Topic | Covers |
|---|---|
| RTO and RPO | Setting them with the business rather than for it |
| Coverage against inventory | Finding what is not backed up |
| Writing a runbook others can follow | |
| Testing | What a restore test proves, and what a tabletop does not |

**Exercise:** Draft recovery objectives for one tier-1 system.

## Module 5 — Security awareness *(all staff with cloud access, 45 min)*

| Topic | Covers |
|---|---|
| Access and least privilege | Why your access is scoped, and how to request changes |
| Credential handling | Password managers, MFA, what never goes in a repository |
| Recognising and reporting | Phishing, suspicious activity, and reporting without blame |
| The access control policy | What it requires of each person |

**Delivered at onboarding and annually thereafter.**
